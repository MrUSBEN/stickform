# Stickform tests

One command checks that nothing broke. It drives the built app (`../../stickform.html`) in a headless browser.

```
npm test             # build, then run every check
npm run test:update  # build, run, and accept the current results as the new baselines
node tests/run.mjs logic ui    # run only some groups: logic, ui, render
```

The console shows a pass/fail count per group and lists only the failures. The full list is in
`tests/output/report.txt`, and `tests/output/contact-sheet.png` shows every preset rendered on the sample
characters, for a quick look by eye.

### Sample characters and an empty `presets/`

The repository ships no sample characters and `presets/` starts empty. Checks that need a character file from
`models/` (Xbot, Soldier, Michelle or the VRM sample; see `../../models/README.md` for where to get them) are
**skipped, not failed**: the run starts with a note naming the missing files, and the summary lists each skipped
check with the file it needed. Likewise the preset-file check is skipped while `presets/` has no pose files. The
built-in mannequin, the ten starter poses (`src/presets.json`) and everything else are still fully tested. Put the
characters in `models/` to run the complete suite. The baseline renders for the sample characters
(`baselines/renders/xbot-*.png`, `vrm-*.png`) are not part of the repository; the first full run with the
characters present writes them.

The test pages set `window.stickformNoLock` so dragging a number box does not lock the pointer (headless Chromium's
pointer lock reports no real movement); in a real browser the drag locks the pointer, like Blender.

## When something fails

- **A change you meant to make** (for example, a tagger improvement that changes a pose on purpose): look at the
  failure, check `tests/output/contact-sheet.png`, then run `npm run test:update` to accept the new results.
- **A change you did not mean to make:** that is a regression. For renders, `tests/output/` holds
  `FAIL-…-now.png` (the new image) and `FAIL-…-diff.png` (changed pixels in red).

## Setup on your own machine (one time)

Needs Node.js 18 or newer. In the `source` folder:

```
npm install
npx playwright install chromium
```

Rendering uses software WebGL (SwiftShader) so images match closely across machines. If the render group fails
everywhere on the first run on a new machine but the contact sheet looks right, run `npm run test:update` once
there to make that machine's baselines.
